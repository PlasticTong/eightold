# 风险控制：先考虑怎么不亏光

策略决定什么时候想交易，风险系统决定能不能交易、交易多少，以及什么时候必须停止。

## 仓位

全仓是教学上的简化，不是推荐做法。实际系统常按单笔可承受亏损计算数量：

```text
交易数量 = 账户权益 × 单笔风险比例 / (入场价 - 止损价)
```

还应限制单资产、单行业、相关资产和账户总风险敞口。

## 最大回撤

最大回撤衡量权益从历史峰值下降的最深幅度：

```text
drawdown = 当前权益 / 历史最高权益 - 1
```

它描述历史最差路径，但不能预测未来最坏情况。尾部风险可能远大于历史样本。

## 实盘系统风控

真实系统至少需要：

- 单笔和单日最大亏损；
- 最大持仓和最大下单数量；
- 价格偏离保护；
- API 限流和重试上限；
- 客户端订单 ID，防止重试造成重复下单；
- 部分成交与撤单处理；
- 本地仓位与券商仓位定期对账；
- 行情过期、断线或时钟异常时停止交易；
- 独立于策略进程的一键停止。

## 当前 Go 系统已经实现

| 参数 | 作用 |
| --- | --- |
| `-max-position` | 限制持仓市值占账户权益的比例 |
| `-lot-size` | 按指定交易单位向下取整 |
| `-stop-loss` | 收盘触发后，在下一根 K 线开盘退出 |
| `-take-profit` | 收盘触发后，在下一根 K 线开盘退出 |
| `-max-drawdown` | 达到组合回撤阈值后退出并禁止后续开仓 |
| `-commission` | 按成交金额计算单边手续费 |
| `-minimum-commission` | 每笔成交的最低手续费 |
| `-slippage` | 买入上浮、卖出下调成交价 |

止损或止盈退出后，策略必须先回到空仓信号，系统才允许下一次开仓，避免同一信号在次日立即重新买入。最大回撤熔断一旦触发，本轮回测不会自动恢复。

## 回测不应遗漏

- 手续费、税费和最低佣金；
- 买卖价差和滑点；
- 涨跌停、停牌与成交量；
- A 股 T+1 和整数手；
- 退市股票和历史指数成分；
- 训练集、验证集、测试集以及 walk-forward。
