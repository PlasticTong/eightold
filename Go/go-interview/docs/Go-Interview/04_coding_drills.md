# Go 手撕题训练板

> 每题按 30 分钟模拟：5 分钟澄清边界，20 分钟实现，5 分钟测试与复杂度说明。

## 通用评分标准

| 维度 | 面试官关注点 |
| --- | --- |
| 边界 | 空输入、重复请求、取消、超时、关闭顺序 |
| 正确性 | 不死锁、不泄漏、不丢任务、没有 data race |
| 可读性 | 小函数、命名清晰、错误向上返回 |
| 复杂度 | 说明时间/空间复杂度与瓶颈 |
| 验证 | 单测、`-race`、并发压测或 benchmark |

## 1. 实现固定并发的 worker pool

要求：给定 `jobs <-chan Job` 和 worker 数量，所有任务完成后退出；支持 context 取消；不能泄漏 goroutine。

追问：

- 生产者比消费者快时，背压在哪里？
- 任务执行 panic 怎么隔离？
- 如何返回第一个错误，同时取消其余任务？

## 2. 并发安全的 TTL 缓存

要求：实现 `Get/Set/Delete`，过期键读不到；不要在每个键上启动一个 goroutine。

追问：

- 用 `Mutex`、`RWMutex`、分片锁分别有什么取舍？
- 清理策略是惰性删除还是定时扫描？
- 热点 key、缓存击穿怎么处理？

## 3. 使用 channel 让两个 goroutine 交替打印奇偶数

要求：打印 1 到 100；能正常结束；不能靠 `time.Sleep` 碰运气。

考点：channel 同步、关闭时机、谁拥有发送权、`WaitGroup`。

## 4. 实现令牌桶限流器

要求：支持每秒生成固定数量令牌、最大桶容量、`Allow()` 非阻塞判断。

追问：令牌桶与漏桶区别？单机方案如何扩展到多实例？高精度计时为什么不能只用固定 ticker？

## 5. 写一个带超时的并发请求聚合器

要求：并发请求多个下游；返回成功结果和失败原因；达到总 deadline 后立即返回并取消未完成请求。

考点：context 传播、结果 channel 容量、提前返回后的发送者阻塞、错误归因。

## 6. 实现 LRU Cache

要求：`Get/Put` 均为 O(1)，容量满时淘汰最久未使用项。

考点：哈希表 + 双向链表；更新已有键时的移动；并发版本的锁粒度。

## 7. 合并多个有序流

要求：输入多个递增 channel，输出一个全局递增 channel；任何输入关闭时要正确处理。

追问：如何控制 goroutine 数量？如果消费者停止读取，生产者如何退出？

## 8. 排查并修复并发 map 的 race

要求：给一段“偶现崩溃”的共享 map 代码，修复后写出 race test。

验证命令：

```bash
go test -race ./...
go test -run TestName -count=100
go test -bench . -benchmem ./...
```

## 提交前自检

- 是否有 goroutine 在函数返回后仍可能向无人接收的 channel 发送？
- 是否可能对已关闭 channel 发送，或由多个发送者关闭同一个 channel？
- 是否持锁调用了可能阻塞的操作？
- 是否为所有外部 I/O 传递了 context 和 deadline？
- 是否写出了最少一组并发边界测试？
