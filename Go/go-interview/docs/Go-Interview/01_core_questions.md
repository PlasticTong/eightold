# Go 高频八股：语言基础与内存

> 每题先用粗体句回答，再补原理和边界。不要只报概念名词。

## 1. slice 是什么？append 一定会扩容吗？

**slice 是指向底层数组的描述符，包含指针、长度和容量；`append` 只有容量不足时才会分配新数组。**

- 切片赋值或作为参数传递时，复制的是描述符，不是全部元素；两个 slice 可能共享底层数组。
- `append` 后要接回返回值：`s = append(s, x)`。扩容后原 slice 与新 slice 可能不再共享数组。
- 面试追问：函数改了 slice 的元素，调用方可能看到；函数内 `append` 导致的新数组，调用方不一定看到。

## 2. map 为什么不能并发读写？怎么选解决方案？

**普通 map 的并发读写会产生数据竞争，运行时可能直接报错；必须把同步策略设计在 map 外。**

| 场景 | 选择 |
| --- | --- |
| 读多写少、键集合稳定 | `RWMutex + map` |
| 需要原子“读-改-写” | `Mutex + map` |
| 键独立、读多、生命周期不固定 | `sync.Map` |
| 极高并发且可分片 | 分片 map（每片一把锁） |

最后用 `go test -race ./...` 检查数据竞争；它是诊断工具，不替代正确设计。

## 3. `new` 和 `make` 的区别？

**`new(T)` 返回 `*T` 的零值指针；`make` 只用于 slice、map、channel，返回初始化后的值。**

- `var m map[string]int` 可读但不能写；`make(map[string]int)` 后才能写。
- `make([]int, len, cap)` 的 `len` 是可直接索引的元素数，`cap` 是可增长上限。
- `make(chan T, n)` 的 `n` 是缓冲容量，改变的是阻塞行为，不是并发安全保证。

## 4. interface 的 `nil` 坑是什么？

**接口值同时保存动态类型和动态值；只有两者都为空时接口才等于 `nil`。**

```go
var p *bytes.Buffer = nil
var r io.Reader = p
fmt.Println(r == nil) // false：接口内有动态类型 *bytes.Buffer
```

工程建议：返回 `error` 时直接返回 `nil`，不要把“类型化 nil 指针”包装进接口。

## 5. `defer`、`panic`、`recover` 的执行顺序？

**defer 后进先出；panic 会展开调用栈并执行 defer；`recover` 仅在延迟函数中、且处于同一 goroutine 的 panic 链上才有效。**

- `defer` 的参数在注册时求值，闭包访问的外部变量在执行 defer 时读取。
- `recover` 适合 HTTP 请求边界或 goroutine 入口，记录错误并隔离单个请求；不应把它当普通错误处理。
- 无法跨 goroutine `recover`：启动 goroutine 的地方必须自己包一层保护。

## 6. 值接收者和指针接收者如何选？

**小型、不可变语义的类型可用值接收者；需要修改状态、避免复制或保持方法集一致时用指针接收者。**

- 若任一方法使用指针接收者，通常整组方法都使用指针接收者。
- `T` 的方法集不包含 `*T` 的指针接收者方法；这会影响接口实现判断。
- 不要仅凭“指针更快”选择；可读性与语义优先，性能用 benchmark 决定。

## 7. 什么是逃逸分析？怎样查看？

**逃逸分析由编译器决定变量能否放在栈上；生命周期无法证明安全时，变量可能逃到堆上。**

```bash
go build -gcflags='-m -m' ./...
```

常见触发因素包括：返回局部变量地址、放入接口、闭包捕获、大小无法静态确定等。不要为“零逃逸”重写业务代码：堆分配是否是瓶颈，要用 `pprof` 和 benchmark 判断。

## 8. 结构体什么时候可比较？

**当且仅当所有字段都可比较时，结构体可用 `==`，也可作为 map key。**

不可比较字段包括 slice、map、func；数组是否可比较取决于元素类型。面试中常追问：含 `[]byte` 的结构体不能直接比较，需要 `bytes.Equal` 或业务定义的比较逻辑。

## 9. 字符串和 `[]byte` 如何取舍？

**string 适合不可变文本，`[]byte` 适合构造和修改；转换可能产生分配，不能想当然。**

- 遍历中文要区分 byte 与 rune：`for range` 解码 rune；索引 `s[i]` 得到 byte。
- 大量拼接优先用 `strings.Builder` 或 `bytes.Buffer`。
- 不要为了省一次转换牺牲所有权边界；对外暴露的 `[]byte` 常需复制，避免被调用方篡改。

## 10. init 的执行顺序？

**包初始化按依赖图进行；同一包内先初始化变量，再执行 `init`，全部初始化完成后才进入 `main.main`。**

工程上避免把网络、数据库连接、长耗时任务放进 `init`：它难以测试、难以控制失败策略，也会拖慢启动。
