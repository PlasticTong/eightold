# 游戏服务器开发学习地图

> 目标：从 Go 后端能力出发，做出一个可运行、可压测、可扩展的多人游戏服务。

游戏服务器不只是“长连接后端”。它的难点在于：一边要让玩家看到一致、顺滑的世界；另一边还要在高并发、弱网络和不可信客户端下保持正确。

## 先建立全局视角

```text
玩家客户端
    │ WebSocket / TCP / UDP
    ▼
网关 ── 登录 / 鉴权 / 限流 / 连接管理
    │
    ├── 大厅：好友、背包、邮件、排行榜、活动
    ├── 匹配：按段位、地区、延迟组队
    └── 战斗服：房间、Tick、规则校验、状态广播、结算
             │
             └── Redis / MySQL / MQ / 日志与监控
```

- **大厅业务**和常规互联网后端相似：重点是幂等、缓存、事务、消息可靠性。
- **战斗服**是实时状态机：重点是 Tick、网络同步、顺序、延迟和反作弊。
- **网关**不要承载游戏规则：它应负责连接和路由，使战斗服可以按房间独立扩容。

## 建议学习顺序

| 阶段 | 你要解决的问题 | 产物 |
| --- | --- | --- |
| 1. 连接层 | 客户端如何稳定连上来？ | WebSocket/TCP 聊天室、心跳、重连 |
| 2. 房间服 | 一局游戏如何独立运行？ | 房间、玩家状态、固定 Tick、广播 |
| 3. 同步 | 卡顿和延迟如何处理？ | 状态快照、插值、预测、校正 |
| 4. 业务 | 游戏外数据如何可靠保存？ | 背包、排行榜、邮件、结算幂等 |
| 5. 扩展 | 人多时如何调度与观测？ | 匹配、服务拆分、压测、监控 |

## 两条最重要的原则

1. **客户端提交意图，服务端决定结果。** 客户端可以说“我要向右移动”或“我要释放技能”，不能直接说“我已经移动到这里”或“我造成了 9999 伤害”。
2. **先正确，再优化。** 先让房间内的状态只有一个明确的拥有者，再考虑锁分片、对象池、二进制协议和多机扩容。

## 延伸阅读

- [Nakama](https://github.com/heroiclabs/nakama)：包含匹配、聊天、排行榜、权威对局等完整能力的开源游戏后端。
- [Pitaya](https://github.com/topfreegames/pitaya)：Go 集群游戏服务器框架，可用来研究网关、RPC 和服务发现。
- [Agones](https://agones.dev/site/docs/)：在 Kubernetes 上托管、调度和扩缩容专用游戏服务器。
